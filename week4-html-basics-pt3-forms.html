🕐 Part 1: HTML5 Semantic Elements

So far we've been using elements like <h1>, <p>, and <ul>. These elements tell us something about their content - a heading, a paragraph, an unordered list. HTML5 introduced even more elements that describe the purpose of different parts of a web page. These are called semantic elements.

Why Use Semantic HTML?

  • Accessibility: Screen readers can better understand your page structure and help visually impaired users navigate
  • SEO (Search Engine Optimization): Search engines like Google can better understand your content
  • Code Readability: It's easier for you and other developers to understand your code
  • Maintainability: Easier to update and modify your website later

The Main Semantic Elements

<header>

The <header> element typically contains introductory content for a page or section. It often includes a logo, site title, and main navigation. 

<header>
  <h1>My Awesome Website</h1>
  <nav>
    <!-- navigation goes here -->
  </nav>
</header>

<nav>

The <nav> element is used for major navigation blocks - typically your main site menu. 

<nav>
  <ul>
    <li><a href="index.html">Home</a></li>
    <li><a href="about.html">About</a></li>
    <li><a href="contact.html">Contact</a></li>
  </ul>
</nav>

<main>

The <main> element contains the main content of your page. There should only be one <main> element per page, and it shouldn't contain content that's repeated across pages (like navigation or footers). 

<main>
  <h1>Welcome to My Page</h1>
  <p>This is the main content...</p>
</main>

<article>

The <article> element represents a self-contained piece of content that could stand alone - like a blog post, news article, or product card. 

<article>
  <h2>How to Make Perfect Coffee</h2>
  <p>Published on Jan 15, 2025</p>
  <p>Coffee making is an art...</p>
</article>

<section>

The <section> element groups related content together. It typically includes a heading and represents a thematic grouping of content. 

<section>
  <h2>Our Services</h2>
  <p>We offer web design, development, and SEO...</p>
</section>

<aside>

The <aside> element contains content that is tangentially related to the main content - like a sidebar, pull-quote, or related links. 

<aside>
  <h3>Related Articles</h3>
  <ul>
    <li><a href="#">10 Coffee Facts</a></li>
    <li><a href="#">Best Coffee Makers</a></li>
  </ul>
</aside>

<footer>

The <footer> element typically contains information about the author, copyright, links to related pages, or contact information. 

<footer>
  <p>&copy; 2025 My Company. All rights reserved.</p>
  <p>Contact: info@mycompany.com</p>
</footer>

A Complete Example

Here's how all these elements work together to create a well-structured HTML5 page: 

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Coffee Blog</title>
  </head>
  <body>
    <header>
      <h1>The Coffee Blog</h1>
      <nav>
        <ul>
          <li><a href="#">Home</a></li>
          <li><a href="#">Recipes</a></li>
          <li><a href="#">About</a></li>
        </ul>
      </nav>
    </header>

    <main>
      <article>
        <h2>The Perfect Espresso</h2>
        <p>Making great espresso takes practice...</p>
      </article>

      <aside>
        <h3>Popular Posts</h3>
        <ul>
          <li><a href="#">Latte Art Tips</a></li>
          <li><a href="#">Best Beans</a></li>
        </ul>
      </aside>
    </main>

    <footer>
      <p>&copy; 2025 The Coffee Blog</p>
    </footer>
  </body>
</html>

Semantic HTML vs Divs

Before HTML5, developers used <div> elements with classes like <div class="header"> or <div class="footer">. Now we can use semantic elements that mean something. However, divs are still very useful for styling and layout - we'll cover them in the next section!

🕑 Part 2: Embedded Content

HTML allows you to embed rich media content into your pages - videos, audio, maps, and even other web pages! This makes your sites more engaging and interactive.

Embedding Videos with <iframe>

The <iframe> (inline frame) element allows you to embed another HTML page within your page. This is most commonly used for embedding videos from YouTube or Vimeo.

Embedding a YouTube Video

  1. Go to the YouTube video you want to embed
  2. Click the "Share" button below the video
  3. Click "Embed"
  4. Copy the iframe code provided
  5. Paste it into your HTML
<iframe
  width="560"
  height="315"
  src="https://www.youtube.com/embed/dQw4w9WgXcQ"
  title="YouTube video player"
  frameborder="0"
  allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture"
  allowfullscreen>
</iframe>

Vimeo Videos

The process is similar for Vimeo - click the "Share" button, then copy the embed code. Vimeo often provides cleaner, ad-free embeds for professional projects.

The <video> Element

For hosting your own video files, HTML5 provides the <video> element. This gives you more control over the player appearance and behavior. 

<video width="640" height="360" controls>
  <source src="videos/my-video.mp4" type="video/mp4">
  <source src="videos/my-video.webm" type="video/webm">
  Your browser does not support the video tag.
</video>

Video Attributes:

  • controls - Displays play/pause buttons
  • autoplay - Starts playing automatically (use sparingly!)
  • loop - Repeats the video
  • muted - Starts with no sound
  • poster - Shows an image before the video plays 
<video width="640" height="360" controls poster="images/video-poster.jpg">
  <source src="videos/intro.mp4" type="video/mp4">
</video>

The <audio> Element

Similar to video, the <audio> element lets you embed audio files like music or podcasts. 

<audio controls>
  <source src="audio/podcast-episode-1.mp3" type="audio/mpeg">
  <source src="audio/podcast-episode-1.ogg" type="audio/ogg">
  Your browser does not support the audio element.
</audio>

Audio Attributes:

  • controls - Shows play/pause controls
  • autoplay - Starts automatically
  • loop - Repeats the audio
  • muted - Starts muted

Embedding Google Maps

Google Maps can also be embedded using an iframe. This is perfect for showing your business location or event venue.

How to Embed a Google Map:

  1. Go to Google Maps
  2. Search for the location you want
  3. Click the "Share" button
  4. Click "Embed a map"
  5. Copy the iframe code
  6. Paste it into your HTML
<iframe
  src="https://www.google.com/maps/embed?pb=!1m18!1m12!1m3!1d..."
  width="600"
  height="450"
  style="border:0;"
  allowfullscreen=""
  loading="lazy">
</iframe>

🕒 Part 3: Divs, Spans, Classes & IDs

Now that you've learned about semantic HTML, it's time to understand the building blocks that help us apply CSS styling: <div> and <span> elements, along with classes and IDs.

The <div> Element

The <div> (division) element is a block-level container. It's used to group elements together so you can style them or position them as a unit. Divs don't have any semantic meaning - they're purely for layout and styling. 

<div>
  <h2>Product Features</h2>
  <p>This product includes amazing features...</p>
  <ul>
    <li>Feature 1</li>
    <li>Feature 2</li>
  </ul>
</div>

When to Use Divs vs Semantic Elements

  • Use semantic elements when the content has meaning: <header>, <nav>, <article>, etc.
  • Use divs when you need a container purely for styling or layout purposes

The <span> Element

The <span> element is an inline container. It's used to style or manipulate a small piece of text within a larger block of content. 

<p>
  This product is available in
  <span style="color: red;">red</span>,
  <span style="color: blue;">blue</span>, and
  <span style="color: green;">green</span>.
</p>

Block vs Inline Elements:

  • Block elements (like <div>, <p>, <h1>) start on a new line and take up the full width
  • Inline elements (like <span>, <a>, <strong>) sit within the flow of text

Classes

Classes are used to identify groups of elements that you want to style the same way. You can apply the same class to multiple elements, and each element can have multiple classes. 

<div class="product-card">
  <h3>Blue T-Shirt</h3>
  <p class="price">£19.99</p>
</div>

<div class="product-card">
  <h3>Red Hoodie</h3>
  <p class="price sale-price">£29.99</p>
</div>

In CSS, you target classes using a dot (.)

.product-card {
  border: 1px solid #ccc;
  padding: 20px;
}

.price {
  font-size: 1.5em;
  color: #333;
}

.sale-price {
  color: red;
  font-weight: bold;
}

Class Naming Conventions:

  • Use lowercase letters
  • Use hyphens to separate words (not underscores or spaces)
  • Make names descriptive: main-nav not mn
  • Examples: product-card, hero-image, contact-form

IDs

IDs are used to uniquely identify a single element on a page. Each ID should only be used once per page. IDs are useful for linking to specific sections and for JavaScript. 

<header id="main-header">
  <h1>My Website</h1>
</header>

<nav id="primary-navigation">
  <ul>
    <li><a href="#about">About</a></li>
    <li><a href="#services">Services</a></li>
  </ul>
</nav>

<section id="about">
  <h2>About Us</h2>
  <p>Information about the company...</p>
</section>

<section id="services">
  <h2>Our Services</h2>
  <p>What we offer...</p>
</section>

In CSS, you target IDs using a hash (#)

#main-header {
  background-color: #333;
  color: white;
  padding: 20px;
}

#about {
  background-color: #f4f4f4;
  padding: 40px;
}

Classes vs IDs: Which Should You Use?

Quick Comparison

  • Classes: Can be used multiple times, target with . in CSS, best for styling groups
  • IDs: Only once per page, target with # in CSS, best for unique elements and page anchors

Best Practice: For beginners, stick to classes for styling and only use IDs for unique elements or when linking to sections. This keeps your CSS more flexible and reusable.

🕓 Part 4: Forms

Forms are an essential part to most websites. We use them all the time to get things done. When you logged on to MyBeckett to view this tutorial you used a Form to enter your username and password, if you bought some items on Amazon you would have used a form element to pay and at some point you would have used a form to store your address details so they could be sent to you.

Forms are used to collect information from a user. This information is usually sent to a program on the server for processing. They can contain input elements like text fields, checkboxes, radio-buttons, submit buttons and more. A form can also contain select lists, textarea, fieldset, legend, and label elements. We will cover all of these elements below.

All forms must be wrapped with the form element

<form method="post" action="script-on-server.php">
  <!-- all of your form content goes here -->
</form>

You will see that there are a couple of additional attributes that have been added to the form element.

The method attribute

method determines how the browser should send any data specified in the form to the server. method can have values of get and post.

With the get method, the browser takes the value specified for the action attribute, appends a ? to it, then appends any form data and sends it as an HTTP call to the web server; you see this in the URL when you submit a form.

post on the other hand achieves the same HTTP transaction without using the URL. This is considered the more secure and preferrable option to use.

The action attribute

This is simply the name of the script on the server that handles the processing of the form information. It is beyond the scope of this module to look at the back-end.

A side note on some new terminology

Front-end vs Back-end

You might occasionally hear me talk about front-end and back-end development. Front-end is what we mainly cover on this course. Everything you are learning on this module is front-end web development. It is concerned with how sites look and the content of websites.

Back-end web development is concerned with the things that you don't see (round the back). These are the scripts that sit on the server that handle data. This would be taught on a more traditional computing degree although if you pick the Web Development module in your final year you will learn a little about PHP which is one of the main languages used in back-end development.

In web agencies if you got a job that involves building websites (coding them) you would tend to get employed as either a front-end developer or a back-end developer.

A simple form

The simplest type of form might be a basic sign-in form where someone enters their username and password to access a website. Let's look at what that might look like. 

<form method="post" action="script-on-server.php">
  <label for="username">Username</label>
  <input type="text" id="username" name="uname">
  <label for="password">Password</label>
  <input type="password" id="password" name="pass">
  <button type="submit">Sign in</button>
</form>

Notice how the type attribute in each input element determines how the browser handles the input and renders its display. Both of these render like text input boxes on the screen but the browser replaces the password field with dots for security.

The <label> element

The <label> element allows us to put text on the screen next to the input boxes so the user knows what type of information the input boxes are expecting. We can link labels to the form fields by using the for attribute on the label and the id attribute on the input element. If the value for both is the same it associates them together. By using labels the user can click on the descriptive text to highlight the form field. This is good for touch devices and for accessibility.

fieldsets and legends

<form method="get" action="sign-in.html">
  <fieldset>
    <legend>Login</legend>
    <label for="username">Username</label>
    <input type="text" id="username" name="uname"><br>
    <label for="password">Password</label>
    <input type="password" id="password" name="pass"><br>
    <button type="submit">Sign in</button>
  </fieldset>
</form>

Try it yourself:

Login

Notice the border around the form inputs and the legend text appearing on the border line!

The <fieldset> element is a way of associating a group of form inputs. For instance you might have a <fieldset> that groups all personal information like name, address and contact number. When you view this in a browser a small border is placed to group the items together. A form can have several fieldsets.

The <legend> element allows you to add a name to your fieldset. This name is displayed as part of the border.

The <input> element

This is the most important form element and can vary in many ways depending on the value of the type attribute - it can be of type text field, checkbox, password, radio button, submit button, and more.

Input Type Text

<input type="text"> is the default setting. If you just typed <input> you would get the same thing so strictly speaking you don't need to add in the type="text" but it is good practice to do this.

The input type of text produces a text box the height of a single line. 

<label for="username">Username</label>
<input type="text" id="username" name="uname" maxlength="30">

Try it yourself:

Try typing more than 30 characters - the field will stop accepting input!

maxlength is an attribute used to limit the number of characters that can be typed into a text field. Normally you can type as many as you want into them and the text will scroll to the left. The example above limits the amount of text to 30 characters.

The name attribute is the variable name that is sent to the script so it can identify the information it is being sent.

Input Type Radio

<input type="radio"> defines a radio button.

Radio buttons let a user select ONLY ONE of a limited number of choices: 

<input type="radio" id="small" name="size" value="small">
<label for="small">Small</label><br>
<input type="radio" id="medium" name="size" value="medium">
<label for="medium">Medium</label><br>
<input type="radio" id="large" name="size" value="large">
<label for="large">Large</label>

Try it yourself:

T-Shirt Size:



Notice how you can only select ONE option - selecting another deselects the previous choice!

Input Type Checkbox

<input type="checkbox"> defines a checkbox.

Checkboxes let a user select ZERO or MORE options of a limited number of choices. 

<input type="checkbox" id="vehicle1" name="vehicle1" value="Bike">
<label for="vehicle1"> I have a bike</label><br>
<input type="checkbox" id="vehicle2" name="vehicle2" value="Car" checked>
<label for="vehicle2"> I have a car</label><br>
<input type="checkbox" id="vehicle3" name="vehicle3" value="Boat">
<label for="vehicle3"> I have a boat</label>

Try it yourself:

Vehicles:



Unlike radio buttons, you can select MULTIPLE checkboxes at once!

Input Type Email

<input type="email"> enables the browser to check that a correct email was added and show an error message if not.

Some smartphones recognize the email type, and add ".com" to the keyboard to match email input. 

<label for="email">Enter your email:</label>
<input type="email" id="email" name="email">
<button type="submit">Sign Up</button>

Try it yourself:

Try entering invalid email (like "test") and click Sign Up - the browser will show an error!

Input Type Date

<label for="dob">Date Of Birth:</label>
<input type="date" id="dob" name="dateofbirth">
<button type="submit">Submit</button>

Try it yourself:

Click the input field to see the calendar picker appear!

When you select the input field it then loads up a calendar in supported browsers.

The required attribute

If we want to make sure that a user enters a specific item we can add an attribute of required to it. The browser will then check to see if it has been added and won't submit the form until it is. Here is another example with this added to each input type: 

<form method="get" action="sign-in.html">
  <label for="email">Enter your email:</label>
  <input type="email" id="email" name="email" required>
  <label for="phone">Mobile number:</label>
  <input type="tel" id="phone" name="phone" pattern="[0-9]{11}" required>
  <button type="submit">Sign Up</button>
</form>

The placeholder attribute

The input placeholder attribute specifies a short hint that describes the expected value of an input field (a sample value or a short description of the expected format).

The short hint is displayed in the input field before the user enters a value.

The placeholder attribute works with the following input types: text, search, url, tel, email, and password. 

<label for="username">Username:</label>
<input type="text" id="username" name="user" placeholder="c7234665">
<label for="pwd">Password:</label>
<input type="password" id="pwd" name="pwd">
<button type="submit">Sign In</button>

Try it yourself:

The placeholder text disappears when you start typing. Notice how the password is hidden with dots!

Other form elements

The Select element

The <select> element defines a drop-down list:

The <option> elements defines an option that can be selected.

By default, the first item in the drop-down list is selected.

To define a pre-selected option, add the selected attribute to the option: 

<label for="cars">Make of car:</label>
<select id="cars" name="cars">
  <option value="volvo">Volvo</option>
  <option value="saab">Saab</option>
  <option value="fiat">Fiat</option>
  <option value="audi">Audi</option>
</select>
<button type="submit">Submit</button>

Try it yourself:

Click the dropdown to see all available options!

Textarea

Using <input type="text"> we can only enter a single line of text. Occasionally we want to add a bigger area to forms - such as if you want someone to add comments.

This is when we use the <textarea> element. It is a multiline text area. We are able to size it using the attributes of rows and cols or we could choose to size it using CSS. 

<textarea rows="10" cols="30" name="driverinstructions" placeholder="If you have delivery instructions for our driver please add them here."></textarea>
<button type="submit">Submit</button>

Try it yourself:

Type multiple lines of text - you can press Enter to create new lines!

The Submit Button

Every form needs a way for users to submit their information! The <button> element with type="submit" creates a submit button that sends the form data when clicked. 

<button type="submit">Submit</button>

You can customize the text on the button to match your form's purpose: 

<button type="submit">Send Message</button>
<button type="submit">Sign Up</button>
<button type="submit">Place Order</button>

Try it yourself:

Try submitting the form without filling in your name - the required field validation will stop you!

Button vs Input Submit

You might also see <input type="submit" value="Submit"> used for submit buttons. While this works, the <button> element is more modern and flexible - you can style it more easily and even add icons or images inside it.
